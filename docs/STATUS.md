## Recompile details (M3)

- Function map: 14,379 entries (2,091 functions plus executable labels used as resume points and switch cases).
- `config/layout.toml` drops two data addresses (`0x001B1790`, `0x001B97F0`) that Ghidra exported as code; they had caused 1,323 unhandled-instruction errors.
- 308 SDK functions are bound to PS2Recomp runtime handlers (HLE). The rest of the SDK code, and all game code, is recompiled as-is.
- 467 warnings are unresolved indirect jumps (`JR`/`JALR`). The recompiler adds fallback dispatch entries for them; switch tables and function pointers are expected in a C++ codebase.

## First smoke run (2026-10-15)

- The runner opens its window (raylib, OpenGL 3.3, 640x448), initializes audio, loads the ELF, applies the `metropolismania-us` override and starts at `0x00100008`.
- It stops at once with `guest-branch:missing-target`: an indirect call from `0x00100A34` (inside `__initialize_cpp_rts`, the Metrowerks static-constructor loop) to `0x001BAEA0`.
- Cause: the static-constructor table at `0x001BCDD0` lists `0x001BAE80`, `0x001BAEA0`, `0x001BAEC0` and `0x001BCD90`. Two of them (`0x001BAEA0`, `0x001BAEC0`) are only reachable through that table, so they are missing from the function map.
- Next step (M4): add them as `entry_points`, then keep going down the upstream triage order.

## Boot triage log (M4)

**Where it is now (2026-10-15):** boots, loads all 10 IOP modules on the IOP emulator, shows the **Natsume logo**, a second logo and the **title screen** (with "(c) 2002 Natsume Inc. (c) 2001 Indi Software / MEDIA FACTORY"), passes the memory card check, starts a **New Game**, reaches the intro movie, and (with `MMPC_SKIP_MOVIES=1`) enters the **city game**: the HUD (Month 4, Year 1, Pop 0, Ar 50%) and cursor render over the sky. The **3D city terrain now renders** (after replacing the runtime's HLE `sceVu0` matrix library with the game's own code). Movies still stall.

Known graphics issues: some colours look off (Natsume logo background), dot artifacts on sprites, and the 3D title model (VU1) is missing. The display flicker is fixed (item 11).

0. **Game flow, from the decompiled code.** `mm_Main` (`0x0012AE20`) runs `mm_App_ctor`, then the main loop `0x001854E0`, which calls the game object's per-frame method `0x0012ABA0` (vtable `0x001BCE60`). That method is a scene state machine: scene A (logos, memory card check, title; `0x00171220`/`0x00170BE0`), scene B (`0x00152910`), scene C (city, `0x00182700`). Trace with `pipeline.py run --env MMPC_TRACE=1`.
1. **Pointer-only functions.** Instead of adding the two constructors by hand, `tools/find_code_pointers.py` (run by `pipeline.py pointers`) scans the ELF for code addresses stored in data or built with `lui`/`addiu`. It keeps targets that start right after a previous function's return or tail call, and that decode as valid R5900 code up to their own return. Two rounds added **97 functions**: the static constructors, standard library and game vtables, and a 76-entry handler table at `0x001B1BF0`. Map now: 2,189 functions.
2. **IOP file access** (`patches/0100`). The sound driver `YYSOUND.IRX` opens its data with ioman `open`/`read`/`lseek`, which the IOP emulator did not implement. The patch adds read-only file access through the host.
3. **TODO handlers and HLE overrides.** SDK functions whose runtime handler is still a TODO (returns -1), plus any matching `[pipeline].force_recompile` patterns, are left as the game's own recompiled code. `ps2_recomp` binds functions to runtime handlers by *name* as well as by the stub list, so the pipeline renders a copy of the function map (`work/funcmap.rendered.csv`) with those functions renamed `<name>_lle`. (The first version only edited the stub list and silently had no effect.)
4. **Memory card directory listing** (`patches/0102`). The game lists the card one entry per call (`sceMcGetDir` mode 0, 1, 2, ...); the runtime ignored the continue mode and returned the first entry forever, so the memory card check never finished.
5. **Debugger overlay** (`patches/0103`). The runtime's ImGui debugger started open and covered the game; it now starts hidden (F1 toggles, `PS2X_DEBUG_UI=1` opens it).
7. **VIF1 stream desync** (now upstream PR #269, `patches/0025`). When a GIF IMAGE transfer was split over two VIF1 DIRECT commands, the runtime took the remaining image quadwords straight from the VIF stream, swallowing the next DIRECT's VIFcode quadword. The interpreter lost sync and garbage MPG/MSCAL commands overwrote VU1 microcode (VU1 ran data at `pc=0x710`). Found with `PS2X_VIF_TRACE=2` (`patches/0104`). After the fix the title flow completes and the game reaches scene B (intro movie).
9. **The 3D city: HLE `sceVu0` library.** In the city, VU1 kicked about 15 MB of GS packets per 2 s but only about 450 primitives were drawn: every vertex came out of VU1 at the same off-screen point with the no-draw bit set. The game builds its camera and projection matrices with Sony's `sceVu0*` library, which the runtime replaces with C++ HLE versions; with `force_recompile = ["sceVu0*"]` the game's own (VU0 macro-mode) code runs instead, and the city draws about 40,000 triangles per 2 s. The terrain (dirt, forest) now renders. A hole in that fix (found 2026-10-18 while porting the home view): the sin/cos step inside `sceVu0RotMatrixX/Y/Z` is the analyzer-named `_sceVu0ecossin` (0x104E88), which hands its result back in `vf4` and `vf5`; the leading underscore kept it out of `force_recompile`, so `ps2_recomp` still bound it by name to the runtime's unrelated public `sceVu0ecossin(dst, angle)`. That handler never touches `vf4`/`vf5`, so every rotation matrix came out of stale registers. `pipeline.py` now treats an underscore-prefixed function whose bare name matches a `force_recompile` pattern the same way (`_sceVu0ecossin_lle`).
10. **Performance.** The city runs at about 5 fps (title and menus at the original 30). A sampling profiler (`PS2X_PROFILE=1`, `patches/0108`) showed ~21% of the game thread writing debug logs (the runtime's aggressive logs, now off: city loading dropped from 22 s to under 1 s), ~40% in the VU1 interpreter (about 3-7 million VU cycles per second against ~14 million needed) and ~27% in the software GS rasterizer. A GS worker thread (`patches/0110`) rasterizes in parallel with the game thread and lifts the city from about 5 to about 9 fps. It is on by default now (`PS2X_GS_THREAD=0` turns it off): the city corruption it seemed to cause earlier was the frame buffer 1 / Z buffer overlap fixed in `patches/0112`. With it on, the GS worker was about 96% busy, so `patches/0114` splits long runs of draws across band threads (up to 6, `PS2X_GS_BANDS=N`), each replaying the run clipped to its own rows with its own CLUT copy and texture page cache. Draws that read VRAM the run has drawn start a new run, and draws that read their own frame or depth buffer stay on one thread. `PS2X_GS_BANDS_VERIFY=1` redraws every banded run serially from the same state and compares VRAM byte for byte: 6,800 runs from boot to the city, no differences. The city reached about 13 fps, with the game thread's VU1 interpreter as the bottleneck (the GS threads idle 55-80% of the time).
    `patches/0115` speeds up the VU1 interpreter's bookkeeping without changing its results: pipeline slots are tracked with bitmasks, so the per-cycle commit and the free-slot searches visit only live entries (in the same index order as before), register stall checks iterate set bits, the decoded instruction pair is no longer copied for every instruction, and XGKICK copies whole qwords. PS2Recomp's own test suite (`pipeline.py test`, 459 tests) gives the same results before and after. City: about 19 fps. `patches/0116` lets the FMAC flag helpers reuse the operands `execUpper` already normalized (about 26 fewer normalizations per instruction): about 20 fps. The rest of the VU1 cost is spread over the cycle-accurate model; a large further step would need a different approach (a faster, less exact mode or ahead-of-time compiled microprograms). Next: ahead-of-time compiled VU1 programs (13 microprograms) and fixing the GS worker race.
    Per-function timing (`MMPC_TRACE_CALLS=1`, override module) settles where a city frame goes: over 2.1 s, 12 frames, the VIF1 kick at the end of each frame (`0x00187290`, which starts the frame's VIF1 DMA chain) takes 1,958 ms, because the runtime runs the whole chain (VIF1 unpacks, VU1 microprograms, GS drawing) synchronously inside that store. The game logic (`mm_GameUpdate`) takes 8 ms in total. So city speed is entirely VU1 plus GS throughput: about 163 ms per frame against 33 ms for 30 fps.
    The runtime's vsync is paced by guest progress as well as host time: a slow frame waits for one vsync, so the vsync count follows the frame rate (about 6 per second in the city). Timing that counts vsyncs runs in slow motion instead of skipping frames.
    **Pre-timed VU1 programs** (`patches/0132` to `0135`, `src/port/vu1aot*`, `docs/VU1_PROGRAMS.md`): every VU1 run starts with idle pipelines and ends drained, so the interpreter's scheduling can be worked out once per program and entry PC as a graph of (pc, timing state) nodes with static stalls and commit points. A run follows the graph and does the arithmetic with the interpreter's own semantics (native ops written once without its queues, fuzzed against it; everything else through its `execUpper` and `execLower`), on a snapshot that is restored when anything unusual happens. Checked three ways against the interpreter: the pair trace of every captured run, the outcome of every captured run, and `PS2X_VU1_VERIFY=1` in the game (about a million runs, no mismatch). The city went from 19.0 to 28.6 fps on average (explore autoplay; the frame kick from 48.5 to 18.3 ms), and holds the game's 30 fps in lighter views. In the heaviest views the frame is about 38 ms: 17 ms of VU1, 3 ms of GS front-end and 10 ms waiting for the CPU rasterizer at the end of the frame, which is the next limit.
11. **Display and flicker.** Output is scaled to 4:3 (`patches/0106`). The heavy flicker had a real cause: the game double-buffers interlaced fields with `sceGsSetDefDBuffDc` (two 640x224 buffers, the odd one drawn half a line lower), and the runtime's HLE version put the second frame buffer at the Z buffer address. Every other field was drawn into a buffer that the depth writes then wiped, so the display alternated between a picture and a black frame. `patches/0112` places the second buffer one buffer after the first (page `0x46`), with the Z buffer after both (`0x8C`).
    The game draws a new field every vsync from a VSync interrupt handler (`0x0019C4C0`) and flips the display between the two buffers each time. Shown one after the other on a monitor, the two fields shimmer by half a line, so `patches/0113` weaves the newest two fields into one 640x448 frame, as a TV does (on while the display alternates every vsync, with hysteresis; `PS2X_DEINTERLACE=off` shows single fields). The two fields can come from different game frames, so the weave is motion adaptive: where a field changed and its pixel does not fit between its vertical neighbours, the line is interpolated instead. Measured with `tools/screenshot.py --burst` and a combing score over the captures: the city is pixel-stable with full 448-line detail (text and clock edges smooth instead of line-doubled), and on the animated title the adaptive weave combs about 12 times less than a plain weave (0.08 against 0.99). The runtime's line-selecting "bob" output is off by default (`patches/0109`, `PS2X_DEINTERLACE=bob`); it only applies to the other interlace mode (SMODE2.FFMD=0, full-height buffers).
12. **Sound.** The game loads its own sound modules (LIBSD, SDRDRV, MODHSYN, MODMIDI, MODSEIN, YYSOUND) on the IOP emulator, but PS2Recomp had no SPU2: register writes went into a map and nothing produced audio. `patches/0117` adds an SPU2 to the IOP emulator: 2 MB sound RAM, both cores with 24 voices each (SPU-ADPCM decoding with loop flags, 4-point Gaussian interpolation, pitch and pitch modulation, noise, ADSR envelopes, volume sweeps), the voice mixer and MMIX gates, core 0 feeding core 1, master volume, capture areas, manual and DMA transfers (IOP DMA 4/7) and the IRQA interrupt (IOP IRQ 9). It runs on IOP time (one sample per 768 IOP cycles) and feeds a raylib audio stream; `PS2X_SPU2=0` turns the output off and `PS2X_SPU2_WAV=file.wav` records everything it produced. The title music and city audio play (checked by recording and by spectrogram). Not yet: AutoDMA input (streamed PCM, used by movies). The game runs slower than real time in heavy scenes, and the SPU2 follows emulated time, so it then produces fewer samples than the host plays: `patches/0120` time-stretches the output (WSOLA, pitch unchanged) to match instead of leaving gaps. Recorded at the title: 253 gaps (21% of the music silent) without it, none with it. `PS2X_SPU2_STRETCH=0` turns it off, `PS2X_HOST_AUDIO_WAV=file.wav` records what the host plays.
    `patches/0118` adds the reverb unit (the PSX/PS2 reverb with 39-tap FIR resampling, PS2 work-area addressing) and `PS2X_SPU2_STATS=1` (core settings every 2 s of audio). `patches/0119` fixes YYSOUND's "Error EffectClear!" at boot: the sound driver clears the reverb work area from its module start code, which PS2Recomp runs without a current IOP thread, so libsd's `WaitEventFlag` for each DMA chunk failed whenever the DMA interrupt had not arrived yet. Now such a wait lets IOP time run to the pending interrupts. The driver then switches reverb off (effect areas parked at the top of sound RAM), so the title and city music play dry, as the game sets them up.
13. **Movies play.** The intro movie (`MISSION1.PSS`) decoded fine through PS2Recomp's FFmpeg-backed libmpeg, but advanced at only a few fields per second, so it looked stalled and the screen showed stale image buffers. The game's movie threads wait for the next field by yielding in a loop (`RotateThreadReadyQueue`); every yield went through the runtime's dispatcher transfer (a C++ exception unwind) while adding almost no emulated time, so a vsync took about 250 ms of host time. `patches/0122` skips the transfer when the yielding thread is alone at its priority, and when 200 yields pass with no wakeup, interrupt or scheduler event it skips emulated time ahead to the next scheduled event (at most one vsync; host time still paces vsync). The movie now runs at full rate and renders cleanly; `MMPC_SKIP_MOVIES` is no longer needed to get past it. `patches/0121` adds `PS2X_MPEG_TRACE=1` (the MPEG layer's diagnostics without an aggressive-log build). Movie sound needs the SPU2's AutoDMA input, still to do.
15. **Movie audio fixed.** The audio packets in the PSS movies have odd lengths (4073 and 4059 bytes after the 4-byte sub-stream header), so every packet the demux dropped put the 16-bit samples one byte out of step, which plays as white noise until another drop happens to realign them. `patches/0128` follows libmpeg: in guest code a demux call stops after each audio packet that has a callback, and continues once the callback has taken it; if the callback refuses (the game's 48 KB audio buffer is full), the call returns the bytes before that packet and the game offers it again on a later call. An incomplete packet at the end of the data is no longer consumed, so a packet handed back is still in the game's ring. The audio recorded with `PS2X_SPU2_WAV` now matches the stream extracted from `MISSION1.PSS` (music, the sweep effect, then speech, with no noise blocks); one audio packet was refused in a 70 s stretch of movie and was delivered on the next call.
14. **Black-frame flicker fixed; movie audio in progress.** With the GS worker thread on, whole black frames appeared now and then (5 of 60 captures during a logo fade; none with `PS2X_GS_THREAD=0`). The presenter read DISPFB first and then waited for the worker to catch up before reading VRAM; during that wait the game flipped and cleared the buffer it had named. `patches/0126` queues the presentation in the worker's command stream instead, under the same lock as GIF processing, so DISPFB and VRAM come from the same point of the drawing; the worker only copies VRAM there and the presenter converts the copy, so the worker is not slowed down. Burst captures of the logos, the title and the city (still and while the camera pans) show no black frames and no half-line shifts. `patches/0127` adds `PS2X_WINDOW_POS=x,y` (open the window there, unfocused); `pipeline.py run` sets it from `game_window_pos` in `work/local.json`. Movie audio: `patches/0123` adds SPU2 AutoDMA input (the PCM the game streams from the PSS), `patches/0125` runs libmpeg stream callbacks inside the demux call in stream order, as libmpeg does (queued, they ran after the game had reused that part of its ring; the same fix as ran-j/PS2Recomp#254). That removed the clipping, but the movie audio is still mostly noise, and about 80% of the audio callbacks refuse their packet because the game's audio buffer is full (libmpeg would stop demuxing there; this HLE drops the packet). Also seen: a block of garbled glyphs under the subtitles while the movie plays.
8. **Movies (before).** `mm_PlayMissionMovie` (`0x0019DE10`) plays `DATA\MPEG\MISSION<n>.PSS` in a blocking loop that polls the pad itself (Start/Cross fades it out). The runtime's MPEG path decodes only a few frames and the picture is garbled, so `MMPC_SKIP_MOVIES=1` (override module) returns "played" at once. With that, the game reaches **scene C, the city**.
6. **Scripted input** (`patches/0101`). `PS2X_PAD_SCRIPT` feeds timed button presses for unattended tests (`pipeline.py run --pad file`).
