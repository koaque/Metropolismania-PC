# src/port: the readable port

Hand-written C++ versions of Metropolismania's own functions. Each one replaces the recompiled
(generated) function at the same address while the rest of the game keeps running as recompiled
code, so the game stays playable at every step. A ported function only counts as done once it
matches its original exactly on the differential tests.

## Files

| File | What it is |
|---|---|
| `guest.h` | Guest memory access (`port::host`, `port::load`, `port::store`), `mm::GuestPtr<T>` (a 32-bit game pointer) and `mm::ps2f` (a float with the PS2 FPU's arithmetic) |
| `abi.h` | `PORT_FN(Name)` and `port::callGuest`: the calling convention between ported and recompiled code |
| `port.h`, `port.cpp` | The registry of ported functions and `port::install` (called by the override module) |
| `difftest.h`, `difftest.cpp` | Capture and replay of differential tests |
| `game_types.h` | Generated by `tools/port_gen.py` from `config/types/*.h`: the game's structs as overlays on guest memory |
| `game_functions.h` | Generated by `tools/port_gen.py` from `config/signatures.txt`: every game function's address and prototype |
| `game_globals.h` | Addresses of global data used by ported code |
| `<subsystem>.cpp` | Ported functions, one file per subsystem (as in `docs/map/`) |

Do not edit the two generated headers; `pipeline.py stage` rewrites them.

## Porting a function

1. Read its decompile (`work/decomp/<ADDR>.c`, after `pipeline.py map`) and its page in `docs/map/`.
   Fix the prototype in `config/signatures.txt` first if it is wrong.
2. Write it in `src/port/<subsystem>.cpp` inside `namespace mm`, named like the game function
   without `mm_` and with exactly the prototype from `game_functions.h`. Add `PORT_FN(Name);`.
3. Rules that keep it exact:
   - Floats are `ps2f`. Never do arithmetic on plain `float`.
   - Game data stays in guest memory: use the structs from `game_types.h`, `port::load`/`store`
     and the addresses in `game_globals.h`, not host copies that outlive the call.
   - Call other game functions by name (`Family_InCity(f)`). Unported ones go through the
     function table to the recompiled code; ported ones are plain C++ calls.
   - Nothing that can block or switch threads (the `Blocks` column in `docs/map/`): those
     functions wait for plan step P6.
4. `pipeline.py stage`, `build`, then `pipeline.py capture --functions <Name>` (a visible run that
   records calls of the original) and `pipeline.py difftest`. Every record must be exact. For a
   function that runs every frame, add `--every N` so the records spread over boot, title and city
   instead of all coming from the first frames.
5. Mark it in `config/port_status.csv` (`ported`, then `verified` once difftested).

`MMPC_PORT_DISABLE=0xADDR,...` (or `all`) runs the generated code again for chosen functions, to
bisect a problem.

## What the difftest compares

Each record holds the CPU state at a call and all of RDRAM and the scratchpad. The replay runs the
original and the ported function from that same state and compares guest memory (except the free
stack below the entry stack pointer), the result register, the stack pointer, the return address
and the callee-saved registers. Effects outside guest memory (GS, sound, files) are not compared
yet. Records are game-derived data and stay in `work/difftest/`.
